## 今日学习内容

### 1. 文件与目录的基本概念

文件可以理解为保存数据或内容的载体，例如：

- Excel 文件
- CSV 文件
- TXT 文件
- Python 文件

目录，也就是文件夹，用来组织文件和其他子目录。

对于 AI Quant Lab，未来获取到的历史行情数据不会全部混在同一个位置，而是需要按照用途、处理阶段或数据类型进行组织。因此，理解文件和目录，是后续建立数据目录结构的第一步。

今天开始建立下面这条基本关系：

```text
Python 对象
→ 文件路径
→ 本地文件
→ 后续重新读取
```

### 2. 相对路径与绝对路径

绝对路径描述文件或目录在电脑中的完整位置，例如 Windows 中从盘符开始的路径。

相对路径不是从盘符开始，而是相对于程序当前工作目录来定位文件。例如：

```text
data/raw/history.csv
```

相对路径能否正确找到目标，取决于程序从哪里启动，以及当前工作目录是什么。

今天理解到，工程项目中不应该把本机的绝对路径直接写死在业务代码中。公司电脑上的盘符、用户名和项目位置可能与其他环境不同，硬编码绝对路径会让代码难以迁移，也不方便在 Windows、Linux 或其他电脑上运行。

### 3. `pathlib.Path`

可以从 `pathlib` 导入 `Path`：

```python
from pathlib import Path
```

然后使用 `Path(...)` 表示一个文件或目录路径：

```python
data_dir = Path("data")
```

这里创建的是一个路径对象，只是在 Python 中表达“这个路径是什么”，并不代表磁盘上已经真实存在名为 `data` 的目录。

同样，下面的代码也只是生成一个路径对象：

```python
raw_dir = Path("data") / "raw"
```

它不会自动创建 `data/raw` 目录。路径的表达、目录的创建和文件的写入，是几个不同的步骤。

### 4. 使用 `/` 拼接路径

`Path` 对象可以使用 `/` 拼接目录和文件名：

```python
raw_dir = Path("data") / "raw"
csv_path = raw_dir / "history.csv"
```

这种写法比手动拼接字符串更清楚，也不需要自己处理 Windows 和 Linux 路径分隔符的差异。

今天开始理解，`pathlib` 不只是让代码写得更短，而是提供了一种更适合工程项目的路径表达方式。

### 5. 工程化路径管理的初步思想

随着项目模块增加，数据路径不应该散落在各个业务文件中，也不应该由每个模块分别写死。

更合理的方向是逐渐建立统一的项目根目录和数据目录，例如：

```text
data/
├── raw/
└── processed/
```

后续可以从稳定的项目根目录生成 `data/raw`、`data/processed` 等路径，再由负责存储的模块统一使用。

这样做可以让：

- 业务代码不依赖某一台电脑的绝对路径
- 原始数据和处理后数据有清晰的存放位置
- CSV 保存与读取使用一致的路径规则
- 后续的数据校验、回测和维护更容易组织

## 今天建立的重要理解

今天真正理解到的内容主要是：

- 文件用于保存数据，目录用于组织文件

- 项目代码不应该依赖某一台电脑上的硬编码绝对路径
- `Path` 创建的是路径对象，不会自动创建真实目录或文件
- 可以使用 `/` 清晰地拼接路径
- 路径管理应该逐步集中，而不是散落在不同业务模块中
- DataFrame 进入本地文件系统之前，首先需要有稳定、清晰的路径规则
