## 今日学习内容

### 1. Module 和 Package

一个 `.py` 文件可以理解为一个 module（模块）。

包含多个模块的目录可以作为 package（包），用于组织一组相关功能。例如：

```text
ibkr/
├── __init__.py
└── connection.py
```

在 `ibkr.connection` 中：

- `ibkr` 是 package
- `connection` 是 module

package 负责组织模块，module 负责承载具体代码。这样的结构可以避免把连接、数据、合约和策略等不同职责都写在同一个文件中。

### 2. `__init__.py` 的作用

导入 package 时，会执行该 package 的 `__init__.py`。

但是，其他 `.py` 文件不会因为与 `__init__.py` 位于同一目录就全部自动加载。只有发生相应 import 时，对应模块才会被加载。

可以在 `__init__.py` 中将内部模块的函数暴露到 package 的命名空间：

```python
# ibkr/__init__.py
from .connection import connect_ibkr, disconnect_ibkr
```

外部代码随后可以写成：

```python
from ibkr import connect_ibkr
```

这里不是把函数代码复制到 `__init__.py`，而是让 `connect_ibkr` 这个名字进入 `ibkr` 的命名空间。

这样可以把“包内部实现”和“包对外接口”分开。即使以后函数从 `connection.py` 移动到其他模块，只要 `ibkr` 对外暴露的接口保持不变，外部调用代码通常不需要修改。

### 3. Python 的 import 搜索机制

`sys.path` 可以理解为 Python 导入 module 或 package 时使用的一组搜索路径。

执行：

```python
import ibkr
```

Python 会沿着这些搜索路径寻找 `ibkr` package。因此，项目的启动位置和运行方式会影响 import 是否成功。

出现 `ModuleNotFoundError` 时，不一定表示文件不存在，也可能是：

- 当前启动位置不合适
- 项目根目录没有进入搜索路径
- 模块使用了不符合当前运行方式的导入写法
- Python 没有按预期识别 package 层级

### 4. `python file.py` 和 `python -m package.module`

直接运行文件：

```bash
python file.py
```

更偏向把该文件作为独立脚本执行。

按模块运行：

```bash
python -m package.module
```

表示按照 package/module 体系定位并运行模块。

在需要 package 上下文、特别是使用相对导入的工程项目中，`python -m package.module` 通常更合适。

### 5. 绝对导入和相对导入

绝对导入从明确的顶层 package 开始：

```python
from ibkr.connection import connect_ibkr
```

相对导入从当前 package 位置开始：

```python
from .connection import connect_ibkr
```

其中：

- `.` 表示当前 package
- `..` 表示上一层 package

相对导入是在 Python 识别出的 package 层级中移动，不是简单按照硬盘上的文件夹层级移动，也不能超过当前识别的顶层 package。

例如模块身份是：

```text
ibkr.data.historical
```

那么顶层 package 是 `ibkr`。即使磁盘上 `ibkr` 外面还有一个项目目录，该项目目录也不会因此自动成为 Python package。

### 6. AI Quant Lab 中推荐的导入方式

package 内部模块互相引用时，可以使用相对导入：

```python
# ibkr/__init__.py
from .connection import connect_ibkr
```

项目入口或 package 外部调用时，优先使用清晰的绝对导入：

```python
from ibkr import connect_ibkr
```

这种方式能让依赖关系更清楚，也方便 package 统一管理对外接口。

### 7. `__all__` 的作用

`__all__` 用来声明 module 或 package 希望公开导出的名字：

```python
__all__ = [
    "connect_ibkr",
    "disconnect_ibkr",
]
```

它最直接影响的是：

```python
from ibkr import *
```

`__all__` 不是下面这种导入能够工作的必要条件：

```python
from ibkr import connect_ibkr
```

真正让 `connect_ibkr` 进入 `ibkr` 命名空间的是：

```python
from .connection import connect_ibkr
```

项目中不推荐大量使用 `import *`，因为它会让代码的依赖关系变得不够清晰。

### 8. Python 下划线命名

今天区分了几类常见命名：

- `_name`：通常表示内部使用，是命名约定，不是严格的权限控制
- `__name`：在 class 中可能触发 name mangling（名称改写）
- `__name__`、`__init__`：Python 定义的特殊双下划线名字

需要注意，`__name` 和 `__name__` 不是同一种形式，作用也不同。

### 9. `__name__` 和程序入口

模块被 import 时，`__name__` 通常是模块的完整名称，例如：

```text
ibkr.connection
```

模块作为程序入口执行时：

```python
__name__ == "__main__"
```

因此常见写法：

```python
if __name__ == "__main__":
    main()
```

本质是在判断当前模块是否作为程序入口执行。被其他模块 import 时，这部分入口代码不会执行。

### 10. `__package__` 和 package 上下文

`__package__` 保存当前模块所属 package 的信息。

例如执行：

```bash
python -m ibkr.contract
```

模块中通常会有：

```python
__name__ = "__main__"
__package__ = "ibkr"
```

模块虽然作为程序入口运行，但 Python 仍然知道它属于 `ibkr` package。这也是 `python -m` 能够更好支持相对导入的重要原因之一。

## 易混淆点

### 文件存在不等于能够成功 import

Python 是否能导入一个模块，不只取决于文件是否存在，还取决于搜索路径、启动位置、运行方式和模块身份。

### 文件夹层级不等于 package 层级

磁盘上的项目根目录只是文件夹，不代表它自动成为 Python package。相对导入依据的是 Python 当前识别出的 package 层级。

### `__init__.py` 不会自动加载同目录所有模块

只有明确执行相应 import，内部模块才会被加载。

### `__all__` 不负责把名字加入 package 命名空间

`__all__` 主要声明 `import *` 时公开哪些名字；在 `__init__.py` 中执行 import，才会让内部函数名进入 package 命名空间。

## 今天建立的重要理解

今天开始从工程结构的角度理解 import：

```text
项目启动方式
→ Python 确定模块身份和 package 上下文
→ 根据 sys.path 搜索 package / module
→ 执行对应模块
→ 将导入的名字加入相应命名空间
```

import 不只是“找到一个文件”，还涉及模块如何被定位、以什么身份运行，以及对外暴露哪些接口。

对于 AI Quant Lab，合理设计 package 的对外接口，可以降低外部代码与内部文件结构之间的耦合，让后续重构更容易。
