## `validation.py` 在数据链路中的职责

在当前的市场数据流程中，`storage.py` 负责数据的保存和读取，`validation.py` 则负责判断读取后的数据是否符合后续处理要求。

整体数据链路可以概括为：

```text
IBKR / CSV
→ pandas DataFrame
→ validation
→ 指标 / 策略 / 回测
```

数据能够从 CSV 或其他数据源读取成 DataFrame，只能说明数据已经进入程序，不代表它的结构和内容一定可靠。只有通过质量校验的数据，才应该继续进入策略、指标和回测模块。

这种职责拆分让存储模块专注于存取，验证模块专注于数据质量，后续业务模块则可以在明确的数据约定上工作，从而减少模块之间的耦合。

### 2. 函数入口、异常与 Fail Fast

验证函数的入口是：

```python
def validate_market_data(frame: pd.DataFrame) -> None:
```

`frame: pd.DataFrame` 表示函数预期接收 DataFrame，`-> None` 表示函数的主要作用是执行校验，而不是返回一份新的业务数据。

通过 `isinstance()`、`raise`、`TypeError` 和 `ValueError`，我能够区分两类错误：

- 输入对象的类型不正确时，使用 `TypeError`
- 对象类型正确，但它的内容或数值不符合要求时，使用 `ValueError`

这也体现了 Fail Fast 的思想：数据刚进入系统时就尽早检查，确定不合法后立即抛出内容明确的异常，不让错误数据继续传递。这样既能更快定位问题，也可以避免错误结果在指标、策略和回测中继续扩散。

### 3. 空 DataFrame 与必要字段检查

`frame.empty` 用于判断 DataFrame 是否为空。在确认数据存在后，再利用列表推导式检查必要字段：

```python
missing_columns = [
    column
    for column in REQUIRED_COLUMNS
    if column not in frame.columns
]
```

这段代码的执行过程是：遍历所有必要字段，检查它们是否存在于 `frame.columns`，再把缺少的字段收集起来。

在：

```python
if missing_columns:
```

中，空列表被视为 False，非空列表被视为 True。结合 f-string 和 `", ".join(...)`，异常信息可以直接指出缺少了哪些字段。

今天理解到，好的异常信息不应只表示“出错了”，还应尽量说明错误原因和具体内容，让后续排查不需要再反向猜测。

### 4. 日期字段验证

原始 CSV 或 DataFrame 中的日期可能仍然是字符串。代码通过：

```python
dates = pd.to_datetime(frame["date"], errors="coerce")
```

尝试将日期列转换为 pandas 日期类型。`errors="coerce"` 会把无法转换的内容变成 `NaT`。这也帮助我进一步区分：日期类型中的无效或缺失值通常表现为 `NaT`，数值中的无效或缺失值通常表现为 `NaN`。

日期转换后，还需要检查：

- `dates.isna().any()`：是否至少存在一个无效或缺失日期
- `dates.duplicated().any()`：是否存在重复日期
- `dates.is_monotonic_increasing`：日期是否按升序排列

量化数据对时间顺序非常敏感。回测需要按照历史到未来的方向推进，收益率、均线、滚动窗口和 `shift` 等计算也都依赖正确的行顺序。因此，日期有效、唯一且升序不只是格式要求，也是后续分析正确性的基础。

### 5. OHLC 缺失值与数值转换

`PRICE_COLUMNS` 是 tuple，转换为 list 后可用于 pandas 多列选择：

```python
frame[list(PRICE_COLUMNS)]
```

由于选出的 OHLC 数据是二维 DataFrame，因此可以使用：

```python
.isna().any().any()
```

第一次 `any()` 得到每一列是否存在缺失值，第二次 `any()` 再判断这些列中是否至少有一列存在缺失。

除了检查原始缺失值，代码还会进行数值转换：

```python
numeric_prices = frame[list(PRICE_COLUMNS)].apply(
    pd.to_numeric,
    errors="coerce",
)
```

`apply()` 将 `pd.to_numeric()` 应用到多个价格列。像 `"180.5"` 这样的字符串可以转换为数值，而 `"abc"` 等无法转换的内容则会因 `errors="coerce"` 变成 `NaN`。

这里的两层检查针对不同问题：

- 先检查原始 OHLC 是否直接缺失
- 再检查看似有内容的值是否真的能够转换为数字

例如，`NaN` 可以在第一层被发现；`"abc"` 未必会被第一层识别，但数值转换后会变成 `NaN`，从而在第二层被发现。

### 6. OHLC 领域规则验证

价格字段都存在且都能转换为数字，仍然不代表一根 K 线一定符合市场逻辑。

通过：

```python
.max(axis=1)
.min(axis=1)
```

可以对每一行的多个价格进行横向比较。`axis=1` 表示沿着列方向处理每一行，也就是检查每一根 K 线内部的价格关系。

high 的校验会比较它与 `open`、`low`、`close` 中逐行最大值的关系。如果 high 低于其中任意一个价格，那么这组 OHLC 逻辑不成立。

low 的校验则会比较它与 `open`、`high`、`close` 中逐行最小值的关系。如果其他价格中存在比 low 更低的值，这组数据同样违反基本市场逻辑。

这一层检查让我看到了基础数据校验与 Domain Validation（领域规则验证）的区别：前者判断数据是否存在、结构和类型是否正确；后者进一步判断数据是否符合实际业务规则。

## 今天建立的重要理解

### 职责分离

```text
storage：保存和读取数据
validation：验证数据是否合格
strategy / backtest：使用已经符合约定的数据
```

将这些职责拆开，可以让每个模块的任务更明确，也让后续修改更容易控制。

### 数据契约

`validate_market_data()` 实际上在逐步表达“什么样的数据才能被视为合格的市场数据”：

1. 输入必须是 DataFrame
2. DataFrame 不能为空
3. 必须包含所有必要字段
4. 日期必须有效、唯一并按升序排列
5. OHLC 不能缺失
6. OHLC 必须能够转换为数值
7. OHLC 字段之间必须符合基本市场逻辑

这些规则从输入对象、数据结构和基础类型逐层进入日期时序和 OHLC 业务关系，体现了从基础规则到领域规则的分层验证思路。
