## 对 backtesting.py 的初步认识

backtesting.py 是一个使用历史市场数据模拟策略运行的 Python 回测框架。它与此前接触的 IBKR API 解决不同问题：

- backtesting.py 基于历史数据执行模拟回测
- IBKR API 用于连接真实或模拟券商环境

目前初步建立的回测链路是：

```text
历史数据
→ Strategy
→ Order
→ Broker
→ Trade
→ Position
→ Cash / Equity
→ Stats
```

对几个核心概念的当前理解是：

- `Strategy`：负责根据数据作出交易决策
- `Order`：策略发出的交易委托或交易请求
- `Trade`：订单执行后形成的交易
- `Position`：当前持仓状态

Strategy 与 Backtest 的分离具有明确的工程意义：

```text
Strategy：定义如何交易
Backtest：定义如何在历史数据中模拟策略运行
```

这样，策略逻辑不需要自己承担完整的撮合、账户状态和统计流程。今天也初步注意到 `_stats.py`、`_util.py` 等内部模块与公共接口分离的组织方式，但还没有深入这些模块的实现。

## 类与对象

今天理解到：

```python
class Car:
    ...
```

定义的是类（Class），它描述一类对象可以拥有哪些状态和行为。

```python
car1 = Car()
car2 = Car()
```

`Car()` 表示根据这个类创建对象。Object 与 Instance 在当前学习阶段可以理解为同一个概念。`car1` 和 `car2` 来自同一个类，但它们是彼此独立的对象，可以保存各自的状态。

对象适合表达需要在一段生命周期内持续存在和变化的状态。对于回测策略，这些状态可能包括当前数据、Broker、参数和已经注册的指标，而不是每次调用方法时都重新从外部传入。

## 父类、子类与继承

README 中的策略示例使用了类似下面的写法：

```python
class SmaCross(Strategy):
    ...
```

这里 `Strategy` 是父类，`SmaCross` 是子类。`SmaCross` 可以继承 `Strategy` 已经提供的能力，再只定义自身与其他策略不同的部分。

当前可以将这种关系理解为：

```text
Strategy
├── buy()
├── sell()
├── data
├── position
└── 其他共同能力

        ↓ 继承

SmaCross
├── init()
└── next()
```

这体现了“父类保存共同能力，子类只负责差异”。如果每个具体策略都重新实现下单、持仓和数据访问等通用能力，不仅会产生重复代码，也难以保证所有策略遵循相同接口。

继承关系可以继续向下延伸，一个类可以同时是上一级的子类和下一级的父类。不过，工程中的继承层级过深会增加阅读和维护成本。今天只理解单继承的基本关系，暂未深入多继承和 MRO。

## `self`：当前对象本身

今天理解了，实例方法中的 `self` 表示当前调用该方法的对象本身。例如：

```python
car1.start()
```

进入：

```python
def start(self):
    ...
```

时，可以理解为：

```text
self → car1
```

因此：

```python
self.data
```

表示访问当前对象的 `data` 属性；而：

```python
self.buy()
```

表示让当前对象调用 `buy()` 方法。

两种写法的区别是：

```text
self.data  → 属性访问
self.buy() → 方法调用
```

`self.xxx` 让同一个类创建出的不同对象可以访问和修改各自的状态，而不会全部依赖一组共享的临时变量。

## `__init__`：建立对象的初始状态

`__init__` 用于对象创建后的初始化。创建对象时，Python 会自动调用它。例如：

```python
car = Car("BMW")
```

会把 `"BMW"` 作为参数传入 `__init__`。在：

```python
self.brand = brand
```

中，右侧 `brand` 是传入的参数，左侧 `self.brand` 是保存在当前对象上的属性。保存后，其他实例方法可以在对象的生命周期中继续访问这个值。

如果子类没有重新定义自己的 `__init__`，它可以沿用父类的初始化逻辑。因此，`SmaCross` 即使没有重复编写 Broker、数据和参数的初始化代码，仍然可以通过继承获得 Strategy 对象需要的状态。

今天暂未深入子类覆盖初始化逻辑时如何使用 `super()`。

## 对真实 `Strategy.__init__` 的理解

今天第一次把面向对象基础正式对应到 backtesting.py 当前的真实源码：

```python
class Strategy(metaclass=ABCMeta):

    def __init__(self, broker, data, params):
        self._indicators = []
        self._broker: _Broker = broker
        self._data: _Data = data
        self._params = self._check_params(params)
```

### 初始化指标列表

```python
self._indicators = []
```

这会给当前 Strategy 对象建立一个空指标列表。列表一开始没有内容，后续由策略逐步注册指标。指标列表属于具体策略实例的状态，而不是每次计算时临时出现的局部变量。

### 保存 Broker

```python
self._broker: _Broker = broker
```

这里：

- `_broker` 是保存在当前 Strategy 对象上的内部属性
- `_Broker` 是类型注解
- `broker` 是初始化时传入的实际对象

保存后，Strategy 在后续调用 `buy()` 等行为时可以继续访问对应 Broker，而不需要每次都重新传入。

### 保存回测数据

```python
self._data: _Data = data
```

这会把当前回测使用的数据保存为 Strategy 对象的内部状态，使其他实例方法能够持续访问同一份数据。

### 检查并保存参数

```python
self._params = self._check_params(params)
```

目前将它理解为连续的两步：

```text
params
→ _check_params(params)
→ 将检查后的结果保存到 self._params
```

这一行不仅保存外部传入的参数，还先通过对象自身的方法进行检查，再将结果作为后续可以使用的内部状态。

`_indicators`、`_broker`、`_data` 和 `_params` 前面的单下划线表示内部实现约定。它不是严格的访问权限，但提示外部使用者不应依赖这些内部细节。

## `_data` 与 `@property data`

今天的源码学习正式停在：

```python
@property
def data(self):
    return self._data
```

`@property` 让使用者可以通过属性形式访问数据：

```python
self.data
```

而不是写成：

```python
self.data()
```

当前理解的接口关系是：

```text
_data → 内部真正保存数据的属性
data  → 通过 @property 暴露的公开属性接口
```

这种设计把内部实现和对外接口分开。未来即使内部获取数据的方式发生变化，外部策略仍可能继续通过稳定的 `self.data` 接口访问数据。

今天也开始区分适合表现为属性和方法的概念：

```text
data / position / equity → 更像对象当前的状态，适合属性
buy() / sell()           → 更像对象执行的动作，适合方法
```

目前只理解 `@property` 的使用效果，还没有系统学习装饰器的完整机制。
